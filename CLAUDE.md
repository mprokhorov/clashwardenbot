# Заметки для Claude

## Рабочие договорённости
- Рабочая ветка: `claude/dev`. Ничего не мержить и не пушить в другие ветки без явной просьбы пользователя.
- Пользователь сам ведёт очередь задач и говорит, что делать дальше. Не предлагать мержи/деплой без запроса.
- **Не опираться на коммиты параллельных веток (`claude/main` и др.)** — там могут быть неверные интерпретации промптов. Источник истины по фичам — слова пользователя в текущей сессии и `docs/*.md`.

## Проект
- Python 3.12 (в коде вложенные f-строки — PEP 701), aiogram 3, asyncpg, APScheduler.
- `requirements.txt` сохранён в UTF-16 LE — аккуратнее при редактировании.
- Один процесс = один клан: `--bot_number` выбирает пару из `CLAN_TAGS`/`TELEGRAM_BOT_API_TOKENS`. Все боты семейства пишут в одну БД.

## База данных (прод)
- PostgreSQL, схема **`public`** (а не `clashwardenbot` из `schema.sql`).
- Read-only доступ: роль `claude_ro`, реквизиты в переменных окружения сессии (искать `POSTGRES_*` / `CLAUDE_RO_*`). Проверка доступности: `pg_isready -h $POSTGRES_HOST -p 5432`.
- Если сеть песочницы не пускает на 5432 — просить пользователя выполнить SQL и прислать результат. В любом случае выполнять **только SELECT**.

## Тесты
- `tests/test_player_ratings.py` — обвязка с фейковой БД для логики рейтинга игроков и вьюх роутера. Запуск: `python3.12` из venv с установленными зависимостями (`pip install -r requirements.txt`), из корня репозитория.

## Статус фич
- Рейтинг игроков (`/player_rating`): реализован, см. `docs/player_rating.md` — там полное ТЗ, принятые решения и открытые вопросы.
- Розыгрыш по рейтингу (`/player_rating_giveaway`): НЕ реализован в `claude/dev`; реализация в `claude/main` не подтверждена пользователем.
